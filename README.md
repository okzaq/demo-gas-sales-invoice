# 売上・請求業務の Google スプレッドシート＋GAS 化（自主制作デモ）

> **本リポジトリは自主制作のポートフォリオです。** 架空の食品卸「サンプル食品卸株式会社」を題材にしたデモであり、
> 実案件の納品物ではありません。実在の会社・人物・住所とは関係ありません。

Excel で回している「売上の入力 → 月末の請求書作成 → 月次の集計」を、Google スプレッドシートと
Google Apps Script（GAS）に置き換えるデモです。売上をプルダウンで入力し、メニューから
**締め日・掛率・税率ごとの消費税を反映した請求書 PDF を Google ドライブに一括作成**できます。

**デモURL（閲覧）**: https://docs.google.com/spreadsheets/d/18zsr1G5ePRxiuqaB621Ynl4qgSIzL_1mFeTKwze2ocQ/edit?usp=sharing
（ログイン不要で、9月分を作成済みの「請求書」「月次集計」シートまで見られます）

**自分で動かして試す**: https://docs.google.com/spreadsheets/d/18zsr1G5ePRxiuqaB621Ynl4qgSIzL_1mFeTKwze2ocQ/copy
（Google アカウントでログインすると「コピーを作成」の画面になります。自分の Google ドライブにコピーして、メニュー「請求業務」から操作できます）

## 何ができるか

| Excel でよくある作業 | このデモでは |
|---|---|
| 取引先ごとに掛率・締め日・端数処理が違い、手で計算し直す | 取引先マスタに設定しておけば、売上を入力した瞬間に適用単価・金額が自動で入る |
| 20日締めの取引先だけ、対象の売上を手で拾う | 締め日から請求対象期間（例: 8/21〜9/20）を自動で判定 |
| 請求書のシートをコピーして取引先ごとに書き換え、PDF で保存 | メニューから1社ずつ、または全取引先分を一括で PDF 作成し、ドライブの月別フォルダに保存 |
| 軽減税率（8%）と標準税率（10%）の混在、インボイス対応 | 税率ごとの対象額・消費税を出し、端数処理は**請求書ごと・税率ごとに1回**（インボイス制度のルール） |
| 月次の売上表をピボットで作り直す | 「月次集計を更新」で、税率別・取引先別・商品別の月次表と、請求月基準の請求額を作成 |

ほかに、返品（マイナス数量）、特価単価、量り売り（小数の数量）、売上のない取引先のスキップに対応しています。
入力ミス（マスタにない商品、数量0 など）があると、その行の自動計算列に「要確認」と理由が出て、
請求書の作成も止まります（エラーの行が請求から漏れるのを防ぐため）。

### メニュー「請求業務」

1. **請求書PDFを作成（取引先を指定）** — 請求月と取引先を選んで1社分を作成
2. **全取引先分の請求書PDFを一括作成** — 請求月を選んで全社分を作成（売上のない取引先はスキップ）
3. **月次集計を更新** — 「月次集計」シートを作り直す
4. 売上入力の自動計算をやり直す ／ デモデータを初期化

PDF の保存先は「スプレッドシートと同じフォルダ / 請求書PDF / 2026-09」です。
同じ月・同じ取引先の請求書を作り直すと、古い PDF はゴミ箱に移して置き換えます。

### 請求書テンプレート ／ 請求書

「請求書テンプレート」は見た目だけを持つシートで、フォントや罫線・ロゴは自由に変えられます。
請求書を作るたびにこれをコピーして「請求書」シートを作り、値を書き込んで PDF にします
（最後に作った請求書が「請求書」シートに残ります）。明細が15行を超えると行を足します（長くなれば PDF は2ページ目に続きます）。
値を書き込むセルの位置は `src/config.ts` の `INVOICE_LAYOUT` にまとめてあります。

### 月次集計

| 表 | 行 × 列 |
|---|---|
| 月別 売上合計（税抜・売上日基準） | 税率区分 × 月 |
| 取引先別 売上（税抜・売上日基準） | 取引先 × 月 |
| 取引先別 請求額（税込・請求月基準） | 取引先 × 請求月 |
| 商品別 売上（税抜・売上日基準） | 商品 × 月 |

20日締めの取引先があると「その月に売った額」と「その月に請求した額」が一致しないため、
どちらの基準かを表題に明記しています。

## 設計方針

### 1. 計算は GAS に依存しない純粋関数にして、テストを厚く書く

掛率・端数処理・消費税・締め日・集計はすべて `SpreadsheetApp` を使わない関数に分け、Jest で
150件のテストを書いています。GAS のエディタ上で請求書を何枚も作って目で確かめる、というやり方では
「20日締めの1月分（前年12/21から）」「2月の30日締め」「ちょうど .5 の四捨五入」「返品でマイナスになった税額」
のような境界を漏れなく確かめられないためです。

金額の計算は浮動小数点を使わず、掛率・数量を整数に直して分数のまま端数処理しています
（`100 × 0.29` を素朴に切り捨てると 28 円になる、といった1円ずれを防ぐ）。

### 2. シートの読み書き・PDF 作成は薄くする

```
シート ──getValues──▶ master.ts（行 → 型付きデータ、入力ミスは行番号付きで集める）
                          │
                          ▼
                     invoice.ts / period.ts / summary.ts（計算。純粋関数）
                          │
                          ▼
                     invoice-view.ts（どのセルに何を書くか。純粋関数）
                          │
シート ◀─setValues── sheets.ts / pdf.ts（書くだけ・PDF にして保存するだけ）
```

GAS 依存のコード（`sheets.ts` / `pdf.ts` / `setup.ts` / `main.ts`）には判断を入れず、
受け取った値を書くだけにしています。シート名・列の並び・請求書のセル位置は `src/config.ts` に集約し、
お客様の今の帳票に合わせるときはここを直します。

### 3. dev / prod の切り替え

自作の TypeScript × GAS × clasp ボイラープレートの仕組みをそのまま使っています。
`.clasp.dev.json`（開発用スプレッドシート）と `.clasp.prod.json`（本番＝公開用スプレッドシート）を用意し、
`npm run push` は必ず dev へ、`npm run push:prod` だけが本番へ反映します。
`npm install` 直後は dev 向きに初期化されるので、うっかり本番に push する事故が起きません。
受託では「お客様が毎日使っている本番シート」を壊さずに改修を試せることが重要なため、この構成にしています。

### 4. Excel からの移行の進め方

1. **今の Excel の計算結果をテストの正解にする** — 過去数か月分の請求書（Excel）から、
   取引先ごとの単価・金額・税率別の消費税・請求額を書き写し、新しいロジックが1円単位で一致することを
   テストで確かめます（例: `tests/fixtures/excel-expected.ts` と `tests/excel-migration.test.ts`）。
   一致しない場合は、Excel の数式（ROUNDDOWN か ROUND か、どこで丸めているか）を確認して仕様を決めます
2. **マスタを移す** — 取引先・商品の一覧を貼り付けると、入力規則に合わない値（掛率の 85 と 0.85 の混在、
   締め日の表記ゆれ、重複した名前）がエラーとして一覧で出るので、ここで整理します
3. **並行稼働** — 1〜2か月は Excel と両方で請求書を作り、金額が一致することを確認してから切り替えます
4. **帳票の見た目を合わせる** — 請求書テンプレートのシートをお客様の今の様式に合わせ、
   セル位置を `config.ts` に反映します

## 技術構成

- Google Apps Script（V8）／ Google スプレッドシート ／ HtmlService のダイアログ
- TypeScript（`module: "none"` で GAS のファイル連結に合わせ、各ファイル末尾の
  `if (typeof module !== "undefined") module.exports = {...}` でテストからだけ参照）
- Jest（ts-jest）
- clasp（dev / prod の2環境）
- PDF はスプレッドシートのエクスポート URL を `UrlFetchApp` で呼んで作成（連続作成時の 429 は間隔をあけて再試行）

## デモの公開手順（作者用）

自分の Google アカウントで、公開用のスプレッドシートを作る手順です。

1. **準備**: `npm install`。https://script.google.com/home/usersettings で「Google Apps Script API」をオンにする
2. **ログイン**: `npm run login`（`clasp login`）
3. **スプレッドシートを作る**: Google ドライブで新しいスプレッドシートを作成（例: 「売上・請求デモ」）し、
   「拡張機能 > Apps Script」を開いてスクリプトを作る。
   - スプレッドシートの ID: URL の `https://docs.google.com/spreadsheets/d/【ここ】/edit`
   - スクリプトの ID: Apps Script の「プロジェクトの設定 > スクリプト ID」
4. **`.clasp.dev.json` を作る**: `.clasp.json.example` をコピーし、`scriptId` と `parentId`（スプレッドシートの ID）を記入。
   公開用と開発用を分けるなら、もう1つスプレッドシートを作って `.clasp.prod.json` も同様に作る
   （どちらも git 管理外）
5. **反映**: `npm run push`（公開用を prod にした場合は `npm run push:prod`）
6. **初期化**: Apps Script のエディタで関数 `setupDemo` を選んで「実行」し、権限を承認する
   （スプレッドシートを開き直すとメニュー「請求業務」が出るので、「デモデータを初期化」からでもよい）。
   続けて「全取引先分の請求書PDFを一括作成」で 2026年9月分を作っておくと、
   閲覧した人にも「請求書」シートと「月次集計」の完成形が見える
7. **共有**: 「共有」→ 一般的なアクセスを「リンクを知っている全員」・「閲覧者」にする
8. **デモURL**: 共有リンクの末尾 `/edit?usp=sharing` を `/copy` に置き換えた
   `https://docs.google.com/spreadsheets/d/【スプレッドシートのID】/copy` を、この README の「デモURL」に記入する。
   開いた人には「コピーを作成」の画面が出て、コピーにはスクリプトも含まれる

コピーした人がメニューを初めて実行すると、Google の承認画面
（「このアプリは Google で確認されていません」）が出ます。自作スクリプトでは通常の表示で、
「詳細 > （プロジェクト名）に移動」で進めます。スプレッドシートの読み書き、ドライブへの PDF 保存、
PDF 作成のための外部リクエストの権限を求めます。

複数の Google アカウントでログインしているブラウザでは、メニューから開く請求月の選択画面が「読み込み中…」のまま
進まないことがあります（ダイアログからサーバー側の関数を呼ぶ `google.script.run` の既知の制約）。その場合は、
シークレットウィンドウで1つのアカウントだけでログインして開くか、Apps Script のエディタでファイル「main.gs」の
関数 `createAllInvoicesFromEditor` を実行してください（直近の請求月で全取引先分の請求書を作り、月次集計も更新します）。

## サンプルデータについて

取引先・商品・売上・発行元の情報はすべて**架空**です（実在の会社・人物・住所・口座とは関係ありません）。
請求書の登録番号は明らかなダミー（`T0000000000000`）です。デモの発行元は課税事業者である前提で計算しています。
